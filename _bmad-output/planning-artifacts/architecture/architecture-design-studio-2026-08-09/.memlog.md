- (constraint) SidebarView union ('explorer'|'scm'|'review'|'brain', ActionRail.tsx:26) renders inside the narrow 'rail' pane body (SidebarHost.tsx), sharing real estate with the file explorer — not sized for a 4-panel workspace (Preview+Inspetor+Árvore+Chat).
- (constraint) Dialog pattern (MCP/SkillStudio: open/onOpenChange boolean, WorkUI.tsx useState) has no state persistence across reload and no rail badge — wrong lifecycle for a session-long multi-panel workspace.
- (constraint) 'viewer' pane + EditorTabs/EditorTabKind (useEditorTabs.ts) already supports non-'file' tab kinds (diff/commit/conflict/review), each keyed by a synthetic path — established extension point for a new tab kind.
- (constraint) HtmlPreview.tsx precedent: sandbox="allow-scripts" iframe, deliberately no allow-same-origin, srcDoc. Documented known limitation: srcdoc has no base URL so relative assets 404; comment defers this to a future 'local-server-backed preview' — exactly what Design Studio's PRD §8 says it cannot inherit unresolved.
- (constraint) whisperProtocol.ts precedent: custom Electron protocol.handle ('hive-model://') registered privileged (standard/secure/corsEnabled/bypassCSP:false) before app.whenReady; CSP is exclusively a static <meta> tag in renderer/index.html, extended one directive at a time per new scheme (e.g. hive-model: only added to connect-src); no session.webRequest CSP header exists anywhere in main.
- (constraint) AgentAdapter interface (main/agentAdapter.ts) + AgentRegistry already generalize Claude/Devin/Copilot CLIs behind one contract (capabilities/startSession/AgentSession/AgentEvent); AgentService + window.hive.agent is the sole renderer→agent routing path, including a runWorkflow guided-intent path used by BMAD skills today.
- (constraint) No undo/redo precedent exists anywhere in the codebase (grep confirms zero hits beyond an unrelated comment) — must be designed fresh for Design Studio, not inherited.
- (constraint) chatHistoryStore.ts precedent: one JSON file per session under <userData>/chat-history/<workspace-hash>/<sessionId>.json, disk-is-source-of-truth (no in-memory cache), write-to-temp-then-rename — the template for any new session-state store.
- (constraint) @hive/design-system (repo root) is a React component library for the Electron shell's own chrome (dropdowns, resizable panels, spinners) — bundled into the renderer as ordinary React imports; unrelated to and not reusable for rendering Design Studio's agent-generated, DS-driven Previews.
- (constraint) IPC convention: flat '<namespace>:<action>' channel names, mirrored in lockstep between preload/index.ts (runtime bridge) and preload/index.d.ts (ambient Window.hive typing), grouped as nested window.hive.<namespace>.* objects.
- (version) Shoelace is archived/renamed as of 2026; successor is 'Web Awesome', npm package @awesome.me/webawesome, MIT-licensed core, built on Lit, ~v3.11.0 per current docs (Aug 2026); a paid Pro tier exists but gates extra icon/theme packs, not the core component set. PRD/addendum's 'Shoelace / Web Awesome' should be read going forward as Web Awesome specifically.
- (decision) [ASSUMPTION] Design Studio mounts as a new EditorTabKind ('design-studio') opened in the existing 'viewer' pane's tab system — one tab per Spec de UX (its Telas switched internally, not one tab per Tela) — NOT a SidebarView, NOT a modal dialog. Diverges from PRD §9's stated assumption (sidebar-view pattern); needs user confirmation and reconciliation back into the PRD.
- (decision) Paradigm: command-sourced document-model editor — one canonical ScreenDocument tree per Tela; every mutation (manual Inspector/Tree edit or Skill de Design System chat response) is expressed as a Command applied through one pipeline — behind a Ports-and-Adapters boundary for the Design System itself (DesignSystemAdapter port; WebAwesomeAdapter the sole v1 concrete adapter).
- (decision) The Skill de Design System never emits final markup — it emits Commands in the same vocabulary as manual Inspector/Tree edits, validated through the same DS-catalog pipeline. This makes 'generation and every edit surface never diverge from the DS catalog' (FR-2/6/7/11, §7 NFR) and 'chat and manual edits share one undo stack' (FR-9) true by construction, not by discipline.
- (decision) Preview isolation: new custom Electron protocol (hive-studio://), registered privileged like whisperProtocol's hive-model:// (corsEnabled, bypassCSP:false), serving the DS Adapter's packaged web-component bundle + a per-session generated HTML shell. Still loaded inside a sandbox="allow-scripts" iframe (no allow-same-origin) via `src`, not `srcDoc` — resolves HtmlPreview.tsx's relative-asset limitation while keeping the opaque-origin isolation guarantee. CSP <meta> must be extended per-directive for the new scheme (frame-src/default-src at minimum, plus img-src/style-src/script-src as needed), following the existing hive-model: append convention.
- (decision) Export Bundle reuses the DS Adapter's own static-render path (renderToStaticHtml), never a second hand-rolled HTML generator — prevents Preview and Export ever rendering a Tela differently.
- (decision) Design Studio session state (per-Tela ScreenDocument + command history for undo/redo + Chat de Iteração Visual transcript) persists as one JSON file per session in userData, keyed by (spec-path-hash + workspace-hash), following chatHistoryStore's disk-is-source-of-truth / write-temp-then-rename pattern. The Spec de UX markdown file itself is never mutated by Design Studio; session state never gets serialized into the workspace.
- (decision) Undo/redo: a linear command stack per Tela; the atomic undo unit is one user-visible action — one manual edit, or all Commands emitted by one chat turn grouped as a single step (matches FR-9's 'desfazer o chat reverte exatamente aquela mensagem'). No existing precedent to inherit; designed fresh.
- (decision) The Skill de Design System routes through the existing AgentAdapter/AgentService/window.hive.agent pipe like the main chat, and must not assume a Claude-specific capability — it is built on the common AgentSession/AgentEvent contract so it works with whichever backend (Claude/Devin/Copilot) the session is configured to use.
- (decision) Manual-edit rejection (FR-6: invalid prop rejected with feedback) and chat-incapability responses (FR-11: explains the limitation) share one CapabilityViolation shape sourced from the DS Adapter's catalog — prevents the two edit surfaces from developing divergent error UX for the same underlying 'not in the DS catalog' case.
- (decision) New IPC namespace designStudio:* / window.hive.designStudio.*, following the existing flat '<namespace>:<action>' convention mirrored in preload/index.ts and index.d.ts — inherited codebase convention, not a new choice.
- (assumption) iframe sandbox="allow-scripts" (no allow-same-origin) is carried forward as sufficient isolation for v1, per PRD §8/§11 Q2 — not re-litigated architecturally here; the dedicated security review the PRD itself calls for is still owed before this ships.
- (question) Figma Agent's exact input contract (single HTML vs multi-file, shadow-DOM flattening, layer/token metadata) is unresolved per PRD §11 Q1. Export Bundle AD is written format-agnostic at the DS-Adapter boundary (renderToStaticHtml) specifically so the concrete output shape can change later without moving the seam. Deferred.
- (question) Whether Second Brain's (M12) versioning pattern is worth reusing for Tela iteration history is explicitly out of MVP scope per PRD §6.2 — left Deferred; today's per-session command stack (in-memory-per-session, persisted but not versioned long-term) is the v1 answer.

- (decision) AD-2 endurecida: Command carrega exatamente uma mudança atômica (SetProp = {componentId, key, value}); validação acontece na construção do Command via DesignSystemAdapter.validate(), antes do dispatch — o reducer é puro e sempre aplica um Command já validado. Fecha o achado adversarial sobre forma do Command / local de validação ambíguos.
- (decision) AD-3/AD-8 endurecidas: o lote de Commands de um turno de chat é validado como um todo antes de qualquer aplicação; ou o lote inteiro comita como um único passo de undo, ou nada é aplicado e retorna um CapabilityViolation. Fecha o achado adversarial sobre atomicidade de lote / exigência da FR-11 de nunca aplicar mudança parcial.
- (decision) AD-8 endurecida: undo/redo implementado como replay-from-origin sobre o log de Commands por Tela (sem um formato de snapshot separado), mantendo Command[] como única representação persistida do documento. Fecha o achado adversarial sobre mecanismo de undo ambíguo.
- (decision) AD-10 com escopo esclarecido: CapabilityViolation cobre apenas rejeições de descompasso com o catálogo (FR-6/11/13); falhas operacionais ganham forma própria (ver AD-11). Fecha a autocontradição apontada pelo adversarial entre o Binds do AD-10 e a tabela de Consistency Conventions.
- (decision) Nova AD-11: falhas operacionais (agente inacessível, falha ao carregar asset do Preview, falha de I/O ao exportar uma Tela) surgem como um OperationError distinto, isolado por unidade de trabalho (uma Tela falhar na exportação não bloqueia as demais, conforme FR-15). Fecha o achado do rubric walker sobre a dimensão de tratamento de erro estar silenciosa.
- (decision) AD-4 endurecida: renderToDom deve construir DOM via APIs seguras (createElement + atribuição de propriedade/atributo), nunca markup com interpolação de string; qualquer prop com forma de URL (href/src) passa por allowlist de esquema (http/https/data:image apenas). renderToStaticHtml (saída em string) fica reservado ao caminho de Export da AD-6, nunca reexecutado dentro do app. Fecha o achado F2 da revisão de segurança (composição Command→DOM sem restrição) e a inconsistência de nomenclatura markup/DOM entre o diagrama de sequência e a AD-4.
- (decision) AD-5 endurecida: respostas de hive-studio:// carregam CSP própria (connect-src 'none' no mínimo, fechando o canal de exfiltração que o sandbox sozinho não fecha) definida por previewProtocol.ts; atualizações do Preview após a navegação inicial usam postMessage para um receptor dentro do frame (também same-origin, construído pela regra segura da AD-4), nunca renavegação — satisfaz a FR-8 sem nunca usar srcDoc. Fecha F1 e F4 da revisão de segurança.
- (decision) AD-5 também fixa empacotamento: o bundle do Web Awesome vai em hive-desktop/resources/ (convenção já existente asarUnpack: resources/** no electron-builder.yml), lido de process.resourcesPath por previewProtocol.ts — não baixado em runtime como os modelos do whisperProtocol, por ser uma dependência de build, não um modelo escolhido pelo usuário. Fecha o achado do rubric walker sobre empacotamento do app buildado estar em silêncio.
- (decision) AD-7 endurecida: a URL por sessão do protocolo de Preview usa um token aleatório inadivinhável gerado no início da sessão, distinto da chave determinística (specPathHash, workspaceHash) do arquivo de sessão em disco; corsEnabled:true no novo protocolo significa que qualquer documento do app poderia, do contrário, construir a URL de outra sessão se ela derivasse de um hash previsível. Fecha F3 da revisão de segurança.
- (decision) Seção Stack corrigida: o tier Pro do Web Awesome trava um conjunto documentado de componentes (Combobox, Date Picker, File Input, Data Grid, gráficos, "Patterns"), não só pacotes de ícone/tema; os componentes específicos que o addendum já nomeia como necessários no v1 (card/tabs/badge/dialog/dropdown/tooltip/formulário básico) estão confirmados como gratuitos, mas isso precisa ser reconferido antes de qualquer trabalho de catálogo (FR-13) se apoiar num componente ainda não checado. Fecha o achado de verificação de versão + o achado do rubric walker sobre a imprecisão do tier Pro.
- (decision) main/designStudio/ como subpasta reconhecida como exceção deliberada à convenção hoje totalmente plana de src/main/ (~60 arquivos, zero subpastas) — justificada pela coesão interna do módulo (6+ arquivos) e por dsAdapter/ precisar de espaço para um segundo adaptador no futuro; sinalizada explicitamente em vez de desviar em silêncio. Fecha o achado do rubric walker sobre desvio de convenção não reconhecido.
